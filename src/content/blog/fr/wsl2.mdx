## Le problème

On est sous Windows, mais on a besoin de `grep`, `ssh`, `git` en natif, d'un environnement Python propre, ou tout simplement de bash. Les solutions classiques : installer un dual boot (lourd, redémarrage obligatoire), monter une VM (lent, gourmand en RAM), ou utiliser Git Bash (limité).

**WSL2** (Windows Subsystem for Linux 2) résout ça proprement. C'est un vrai noyau Linux qui tourne dans une VM légère, gérée par Windows. On a un terminal Linux complet, avec accès aux fichiers Windows et vice versa, sans redémarrer, sans partition dédiée.

---

## Pourquoi WSL2 et pas WSL1

WSL1 traduisait les appels système Linux en appels Windows. Ça marchait pour les cas simples, mais beaucoup de logiciels posaient problème (Docker, bases de données, outils bas niveau).

WSL2 utilise un vrai noyau Linux dans une VM Hyper-V ultra légère. Le résultat : compatibilité quasi totale et performances bien meilleures sur les opérations fichiers Linux.

## Installation

### Prérequis

- Windows 10 version 2004+ ou Windows 11
- La virtualisation activée dans le BIOS (VT-x / AMD-V)

### Installer WSL2

Ouvrir un terminal PowerShell **en administrateur** :

```powershell
wsl --install
```

C'est tout. Cette commande active les composants nécessaires, télécharge le noyau Linux et installe Ubuntu par défaut. Un redémarrage est demandé.

Après le redémarrage, Ubuntu se lance et demande de créer un utilisateur et un mot de passe.

### Vérifier l'installation

```powershell
wsl --version
```

---

## Choisir une distribution

Ubuntu est installée par défaut, mais on peut en ajouter d'autres.

### Lister les distributions disponibles

```powershell
wsl --list --online
```

### Installer une distribution spécifique

```powershell
wsl --install -d Debian
```

### Quelques distributions disponibles

| Distribution | Usage typique |
|---|---|
| Ubuntu | Polyvalente, large communauté |
| Debian | Stabilité, serveurs |
| Kali Linux | Sécurité, pentesting |
| Alpine | Ultra-légère (~5 Mo) |

### Définir la distribution par défaut

```powershell
wsl --set-default Ubuntu
```

## Utilisation de base

### Lancer WSL

```powershell
wsl
```

### Installer des paquets

On est dans un vrai Linux, donc les commandes habituelles fonctionnent :

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install build-essential python3 nodejs -y
```

### Lancer une commande Linux depuis PowerShell

Pas besoin d'ouvrir un terminal WSL pour une commande rapide :

```powershell
wsl grep -r "TODO" ./src/
```

---

## Accès aux fichiers

### Accéder aux fichiers Windows depuis WSL

Les disques Windows sont montés automatiquement :

```bash
ls /mnt/c/Users/
cd /mnt/d/Projets/
```

### Accéder aux fichiers WSL depuis Windows

Dans l'explorateur de fichiers, taper dans la barre d'adresse :

```
\\wsl$\Ubuntu\home\
```

Ou depuis le terminal WSL :

```bash
explorer.exe .
```

Ça ouvre l'explorateur Windows directement dans le dossier courant de WSL.

---

## Applications graphiques

Depuis Windows 11, WSL2 supporte nativement les applications graphiques Linux (WSLg). Pas de serveur X à configurer.

```bash
sudo apt install gedit -y
gedit
```

L'éditeur se lance dans une fenêtre Windows, comme n'importe quelle application.

---

## Intégration avec VS Code

VS Code s'intègre parfaitement avec WSL2 via l'extension **Remote - WSL**. Elle permet d'ouvrir un projet WSL directement dans VS Code, avec le terminal, le débogueur et les extensions qui tournent côté Linux.

```bash
# Depuis un dossier dans WSL
code .
```

VS Code s'ouvre côté Windows mais travaille côté Linux. Les extensions s'installent dans WSL, le terminal intégré est un shell Linux. C'est transparent.

---

## Docker dans WSL2

**Docker Desktop** utilise WSL2 comme backend par défaut. C'est la façon recommandée de faire tourner Docker sous Windows.

Une fois Docker Desktop installé avec le backend WSL2 activé :

```bash
docker run hello-world
docker compose up -d
```

Les conteneurs tournent dans le noyau Linux de WSL2, avec des performances proches du natif.

Pour ceux qui préfèrent Docker sans Docker Desktop :

```bash
sudo apt install docker.io -y
sudo usermod -aG docker $USER
```

## Commandes de gestion utiles

```powershell
# Arrêter WSL
wsl --shutdown

# Exporter une distribution (backup)
wsl --export Ubuntu ubuntu-backup.tar

# Importer une distribution
wsl --import MaDistro C:\WSL\MaDistro ubuntu-backup.tar

# Supprimer une distribution
wsl --unregister Debian
```

## WSL2 vs les alternatives

| | WSL2 | Dual boot | VM (VirtualBox) |
|---|---|---|---|
| Noyau Linux | Oui (réel) | Oui | Oui |
| Performance | Proche du natif | Native | Réduite |
| Redémarrage nécessaire | Non | Oui | Non |
| Accès fichiers Windows | Oui (`/mnt/c`) | Possible | Dossier partagé |
| Apps graphiques | Oui (WSLg) | Oui | Oui |
| Docker | Oui | Oui | Oui |
| Espace disque | ~1-2 Go | Partition dédiée | ~10-20 Go |

---

## Les limites

- Pas d'accès direct au matériel (USB limité).
- Les performances sur les fichiers stockés côté Windows (`/mnt/c`) sont nettement plus lentes que sur le système de fichiers Linux natif.
- Consomme de la RAM : par défaut WSL2 peut prendre jusqu'à 50% de la RAM, mais c'est configurable via `.wslconfig`.
- Nécessite Hyper-V, ce qui peut entrer en conflit avec d'autres logiciels de virtualisation.

---

## Conclusion

WSL2 a transformé Windows en plateforme de développement viable pour ceux qui dépendent d'outils Linux. On a un vrai terminal, un vrai noyau, Docker, des applications graphiques, et tout ça sans quitter Windows.

Pour un dev qui travaille sur des projets Linux mais doit rester sous Windows, WSL2 supprime la plupart des frictions. Combiné avec VS Code et Docker, on obtient un environnement de développement complet.
