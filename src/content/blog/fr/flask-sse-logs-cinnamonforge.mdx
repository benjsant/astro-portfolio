**CinnamonForge** est une interface web pour automatiser la post-installation d'un environnement Fedora Cinnamon — installation de paquets par profil, configuration dconf, gestion de thèmes GTK. Le problème : une installation Flatpak peut prendre 3 minutes. Sans feedback visuel, l'utilisateur ne sait pas si l'application est bloquée ou si `dnf` télécharge 800 Mo de dépendances.

La solution : les **Server-Sent Events** — une connexion HTTP unidirectionnelle qui pousse les lignes de log au navigateur au fur et à mesure que les commandes Bash s'exécutent.

---

## Architecture blueprints

```
web_app.py
  ├── routes/
  │     ├── profiles.py    → /api/profiles (liste, activation)
  │     ├── packages.py    → /api/packages/install
  │     ├── dconf.py       → /api/dconf/apply
  │     ├── themes.py      → /api/themes/install
  │     ├── greeter.py     → /api/greeter/configure
  │     ├── system.py      → /api/system/update
  │     └── logs.py        → /api/logs/stream  ← SSE endpoint
  ├── schemas/             → Pydantic v2 validation
  ├── shared.py            → logger partagé entre routes
  └── state_manager.py     → rollback avec state.json
```

Chaque route est un Blueprint Flask séparé. `web_app.py` les enregistre tous avec un préfixe commun :

```python
from routes.logs import logs_bp
from routes.packages import packages_bp
# ...

app = Flask(__name__)
app.register_blueprint(logs_bp, url_prefix='/api/logs')
app.register_blueprint(packages_bp, url_prefix='/api/packages')
```

La séparation en blueprints permet de tester chaque route indépendamment et d'isoler les imports — `themes.py` n'importe pas ce dont `dconf.py` a besoin.

## Le logger partagé dans `shared.py`

Le problème central du SSE dans un contexte multi-thread : plusieurs routes d'installation écrivent des logs, un seul endpoint les lit. La synchronisation se fait via une `queue.Queue` thread-safe :

```python
# shared.py
import queue
import logging

log_queue: queue.Queue[str] = queue.Queue(maxsize=1000)

class QueueHandler(logging.Handler):
    def emit(self, record: logging.LogRecord):
        msg = self.format(record)
        try:
            log_queue.put_nowait(msg)
        except queue.Full:
            pass  # On ne bloque jamais le thread d'installation

logger = logging.getLogger('cinnamonforge')
logger.setLevel(logging.DEBUG)
logger.addHandler(QueueHandler())
```

`maxsize=1000` avec `put_nowait` : si la queue est pleine (client SSE déconnecté, logs trop rapides), on ignore silencieusement le message plutôt que de bloquer le thread d'installation. L'installation continue — les logs perdus sont un problème d'affichage, pas un problème fonctionnel.

## L'endpoint SSE

```python
# routes/logs.py
from flask import Blueprint, Response, stream_with_context
from shared import log_queue
import queue

logs_bp = Blueprint('logs', __name__)

@logs_bp.get('/stream')
def stream_logs():
    def generate():
        yield "data: Connexion établie\n\n"

        while True:
            try:
                # Timeout de 15s — envoie un keepalive si pas de log
                msg = log_queue.get(timeout=15)
                # Échapper les newlines : SSE interprète \n comme fin d'événement
                safe = msg.replace('\n', ' ')
                yield f"data: {safe}\n\n"

                if msg.strip() == '__DONE__':
                    break

            except queue.Empty:
                yield "data: \n\n"  # keepalive SSE

    return Response(
        stream_with_context(generate()),
        mimetype='text/event-stream',
        headers={
            'Cache-Control': 'no-cache',
            'X-Accel-Buffering': 'no',  # désactive le buffering nginx
            'Connection': 'keep-alive',
        },
    )
```

`stream_with_context` est nécessaire dans Flask — sans lui, le générateur n'a pas accès au contexte de requête et Flask lève une `RuntimeError` à la première utilisation d'un proxy de contexte.

Le keepalive toutes les 15 secondes (`yield "data: \n\n"`) évite que les proxies (nginx, Cloudflare) ferment la connexion idle. Un événement SSE vide est ignoré par le navigateur mais maintient la connexion TCP active.

Le signal `__DONE__` dans la queue termine proprement le générateur côté serveur — la connexion SSE se ferme après la dernière ligne de log, sans que le client doive poller ou deviner quand l'installation est terminée.

## Déclencher une installation et logger en parallèle

```python
# routes/packages.py
import subprocess
import threading
from flask import Blueprint, request
from shared import logger, log_queue
from schemas.packages import InstallRequest
from state_manager import StateManager

packages_bp = Blueprint('packages', __name__)

@packages_bp.post('/install')
def install_packages():
    body = InstallRequest.model_validate(request.get_json())

    def run_install():
        state = StateManager()
        try:
            for package in body.packages:
                logger.info(f"Installation de {package}...")
                result = subprocess.run(
                    ['dnf', 'install', '-y', package],
                    capture_output=True,
                    text=True,
                    timeout=300,
                )

                if result.returncode != 0:
                    logger.error(f"Échec : {package}\n{result.stderr}")
                    state.mark_failed(package)
                else:
                    logger.info(f"✓ {package} installé")
                    state.mark_installed(package)

        finally:
            log_queue.put('__DONE__')

    # Thread daemon — s'arrête si Flask s'arrête
    t = threading.Thread(target=run_install, daemon=True)
    t.start()

    # Réponse immédiate — le client suit les logs via SSE
    return {'status': 'started', 'count': len(body.packages)}, 202
```

Le `POST /install` retourne `202 Accepted` immédiatement — l'installation tourne dans un thread séparé. Le client ouvre ensuite la connexion SSE pour suivre la progression. Ce découplage est important : si le client ferme la connexion SSE (tab fermé), l'installation continue dans le thread daemon.

`timeout=300` sur `subprocess.run` évite qu'un `dnf` bloqué sur un miroir indisponible gèle le thread indéfiniment.

## Validation Pydantic v2 des entrées

```python
# schemas/packages.py
from pydantic import BaseModel, field_validator
import re

SAFE_PACKAGE_RE = re.compile(r'^[a-zA-Z0-9_\-\.]+$')

class InstallRequest(BaseModel):
    packages: list[str]
    dry_run: bool = False

    @field_validator('packages')
    @classmethod
    def validate_packages(cls, packages: list[str]) -> list[str]:
        if not packages:
            raise ValueError("La liste de paquets est vide.")
        if len(packages) > 50:
            raise ValueError("Maximum 50 paquets par requête.")

        for pkg in packages:
            if not SAFE_PACKAGE_RE.match(pkg):
                raise ValueError(
                    f"Nom de paquet invalide : '{pkg}'. "
                    "Seuls les caractères alphanumériques, tirets et points sont autorisés."
                )

        return packages
```

La validation du nom de paquet avec la regex `[a-zA-Z0-9_\-\.]+` empêche l'injection de commandes (`; rm -rf /`, `$(evil)`, etc.) avant que le nom arrive dans `subprocess.run`. C'est la frontière système — tout ce qui passe par là doit être validé.

`subprocess.run` avec une liste de strings (pas une string) désactive l'interprétation shell (`shell=False` par défaut) — même si la validation échouait, le shell ne verrait jamais les arguments.

## Rollback avec `state.json`

```python
# state_manager.py
import json
from pathlib import Path
from datetime import datetime

STATE_FILE = Path('data/state.json')

class StateManager:
    def __init__(self):
        STATE_FILE.parent.mkdir(exist_ok=True)
        self.state = self._load()

    def _load(self) -> dict:
        if STATE_FILE.exists():
            return json.loads(STATE_FILE.read_text())
        return {'installed': [], 'failed': [], 'dconf_applied': [], 'last_run': None}

    def _save(self):
        STATE_FILE.write_text(json.dumps(self.state, indent=2))

    def mark_installed(self, package: str):
        self.state['installed'].append({
            'name': package,
            'at': datetime.utcnow().isoformat(),
        })
        self._save()

    def rollback(self) -> list[str]:
        """Désinstalle les paquets installés lors de la dernière session."""
        installed = [p['name'] for p in self.state.get('installed', [])]
        if not installed:
            return []

        subprocess.run(['dnf', 'remove', '-y'] + installed, check=True)

        self.state['installed'] = []
        self._save()
        return installed
```

`state.json` est mis à jour après chaque paquet installé avec succès — si l'installation s'interrompt à mi-chemin, le rollback ne désinstalle que ce qui a réellement été installé, pas ce qui était prévu.

## Ce que j'ai appris

**`stream_with_context` est obligatoire dans Flask.** Sans lui, le générateur SSE n'a pas accès au contexte de requête Flask. L'erreur ne se manifeste pas immédiatement — elle apparaît dès qu'une route dans le générateur tente d'accéder à `request` ou `g`.

**Séparer le déclenchement (POST) du suivi (GET SSE).** Un POST qui bloque jusqu'à la fin de l'installation timeout en 30-60 s sur la plupart des clients HTTP. Le 202 immédiat + SSE séparé permet des installations de plusieurs minutes sans friction.

**`put_nowait` plutôt que `put` dans un handler de logging.** Le thread d'installation ne doit jamais se bloquer sur une queue pleine. Un log perdu est acceptable — un thread d'installation bloqué indéfiniment ne l'est pas.

**Valider les entrées système à la frontière, pas au fond.** La regex sur les noms de paquets est dans le schéma Pydantic, avant tout code d'installation. Valider au plus tôt réduit la surface d'injection — et Pydantic v2 retourne une erreur structurée que le frontend peut afficher directement.
