## Pourquoi un site statique

Quand on veut créer un blog technique, la première idée c'est souvent WordPress. Sauf que WordPress, c'est une base de données, du PHP, des mises à jour de sécurité, des plugins qui cassent, et un hébergement payant. Pour écrire des articles en Markdown avec des blocs de code, c'est overkill.

**Hugo** est un générateur de sites statiques (SSG). On écrit ses articles en Markdown, Hugo génère des fichiers HTML/CSS/JS, et on les déploie. Pas de base de données, pas de backend, pas de serveur à maintenir. Le site est rapide, sécurisé, et gratuit à héberger.

---

## Pourquoi Hugo plutôt qu'un autre

Il existe des dizaines de générateurs de sites statiques. Hugo se distingue sur plusieurs points :

- **Vitesse** : écrit en Go, Hugo génère un site de centaines de pages en moins d'une seconde.
- **Un seul binaire** : pas besoin d'installer Node.js, Ruby ou Python.
- **Écosystème de thèmes** : des centaines de thèmes disponibles, bien documentés.
- **Markdown natif** : on écrit en Markdown, on ajoute du front matter YAML/TOML, et c'est tout.

## Installation

### Linux (Debian/Ubuntu)

```bash
sudo apt install hugo
```

Pour la dernière version depuis GitHub :

```bash
wget https://github.com/gohugoio/hugo/releases/download/v0.142.0/hugo_extended_0.142.0_linux-amd64.deb
sudo dpkg -i hugo_extended_0.142.0_linux-amd64.deb
```

### Linux (Fedora)

```bash
sudo dnf install hugo
```

### macOS (via Homebrew)

```bash
brew install hugo
```

On vérifie :

```bash
hugo version
```

## Créer un site

```bash
hugo new site mon-blog
cd mon-blog
git init
```

Hugo crée une arborescence propre :

```
mon-blog/
├── archetypes/     # Modèles pour les nouveaux contenus
├── content/        # Les articles (Markdown)
├── layouts/        # Templates personnalisés
├── static/         # Fichiers statiques (images, CSS)
├── themes/         # Thèmes installés
└── hugo.toml       # Configuration du site
```

---

## Installer un thème

On installe un thème comme sous-module Git :

```bash
git submodule add https://github.com/nunocoracao/blowfish.git themes/blowfish
```

Puis on configure dans `hugo.toml` :

```toml
baseURL = "https://mon-blog.netlify.app/"
languageCode = "fr"
title = "Mon Blog Technique"
theme = "blowfish"
```

## Écrire un article

```bash
hugo new content/articles/mon-premier-article/index.md
```

Hugo génère un fichier avec le front matter. On le complète :

```markdown
---
title: "Mon premier article"
date: 2026-03-19
draft: false
tags: ["Terminal", "Bash"]
summary: "Un article pour tester Hugo."
---

## Introduction

Voici du texte en **gras** et en *italique*.

```bash
echo "Hello World"
```
```

Si on connaît déjà Markdown, il n'y a rien de nouveau à apprendre.

## Prévisualiser en local

```bash
hugo server -D
```

Le `-D` inclut les articles en mode brouillon. Le site est accessible sur `http://localhost:1313`. Hugo surveille les fichiers et recharge la page automatiquement.

## Déployer sur Netlify

**Netlify** permet de déployer un site statique gratuitement, avec déploiement automatique à chaque push Git.

### 1. Pousser le code sur GitHub

```bash
gh repo create mon-blog --public --source=. --push
```

### 2. Configurer Netlify

On crée un fichier `netlify.toml` à la racine :

```toml
[build]
  publish = "public"
  command = "hugo --minify"

[build.environment]
  HUGO_VERSION = "0.142.0"
```

### 3. Connecter Netlify au dépôt

- Aller sur [netlify.com](https://www.netlify.com/) et se connecter avec GitHub.
- Cliquer sur "Add new site" > "Import an existing project".
- Sélectionner le dépôt GitHub.

C'est tout. À chaque `git push`, Netlify rebuild le site et le déploie en moins de 30 secondes.

## Le workflow au quotidien

```bash
# Créer l'article
hugo new content/articles/mon-article/index.md

# Prévisualiser
hugo server -D

# Publier
git add .
git commit -m "nouvel article : mon sujet"
git push
```

Netlify s'occupe du reste. Pas de FTP, pas de cPanel, pas de base de données à sauvegarder.

## Les limites

- **Pas de contenu dynamique** : pas de commentaires natifs, pas de formulaire sans service tiers.
- **Courbe d'apprentissage** : il faut être à l'aise avec Git, le terminal et Markdown.
- **Personnalisation des thèmes** : modifier un thème en profondeur demande de comprendre le système de templates Go de Hugo.

## Hugo vs les alternatives

| | Hugo | WordPress | Jekyll | Gatsby |
|---|---|---|---|---|
| Vitesse de build | Ultra-rapide | N/A (dynamique) | Lent | Lent |
| Hébergement gratuit | Oui | Non | Oui | Oui |
| Base de données | Non | Oui (MySQL) | Non | Non |
| Dépendances | Aucune (un binaire) | PHP + MySQL | Ruby + gems | Node.js + npm |
| Adapté pour | Blogs techniques, docs | Tout type de site | Blogs, docs | Sites complexes |

Pour un blog technique, Hugo est le meilleur compromis entre simplicité, performance et coût.

## Conclusion

Hugo + Netlify, c'est la stack idéale pour un blog technique. On écrit en Markdown, on push sur Git, et le site est en ligne en quelques secondes. Pas de serveur, pas de base de données, pas de facture d'hébergement.

Si tu es à l'aise avec le terminal et Git, il n'y a aucune raison de se compliquer la vie avec autre chose.
